## Contributing

Read [`AGENTS.md`](AGENTS.md) first. In short:

- One feature per PR, complete (migration plus the code that uses it), small enough to review in one sitting. Chain PRs when one depends on another.
- No personal information or secrets in the repo: no emails, phone numbers, or keys in code, `.env.example`, commits, or PR text.
- Plain commit messages, with no AI-attribution trailers.
- When a feature changes what the app collects, stores, or shares, update the Terms of Service and Privacy Policy in the same PR, or flag it in Deployment Notes if those pages do not exist yet.
